Hapuppy uses a **credit-based** system. You buy credits once, they enter your **vault**, and they never expire. Every API call deducts credits based on the model and the work it did.

## The Vault

Credits you purchase enter a personal **vault** tied to your account.

- **Never expire** — use them at your own pace
- **Stack on top of each other** — buying a Standard pack while a Lite is partly consumed simply adds 120M to your remaining balance
- **Independent of the free tier** — your 100K daily free allowance is consumed first; the vault is only drawn down when the daily allowance runs out
- **Not refundable after significant use** — see refund policy on the dashboard

## How Credits Work

Two billing formulas, depending on the endpoint:

### Token-based (chat, embeddings)

```
credits_charged = total_tokens × model_multiplier
```

Where:
- `total_tokens` = prompt tokens + completion tokens (returned in the `usage` object of every response)
- `model_multiplier` is published per model (see table below)

### Fixed-cost (images, audio, video, moderation)

```
credits_charged = fixed_base_cost
```

Each request deducts a fixed amount that depends on the model and parameters (resolution, duration, etc.) — not on token count.

## Example Calculation

You send a prompt to `gpt-4o` with 800 prompt tokens and receive a 1,200-token response:

```
total_tokens     = 800 + 1200 = 2000
model_multiplier = 1.0
credits_charged  = 2000 × 1.0 = 2,000 credits
```

If your vault has 30M credits, you can run this call about **15,000 times** before topping up.

For a higher-cost model like Claude Opus (5×):

```
credits_charged = 2000 × 5.0 = 10,000 credits
```

You'd get **3,000 calls** from the same vault.

## Rate Limiting

All API keys share a single rate limit: **100 requests per minute (RPM)**. Exceeding this returns a `429` error with:

```json
{
  "error": {
    "message": "Rate limit exceeded. Please retry after 1 second.",
    "type": "rate_limit_error",
    "code": "rate_limit_exceeded"
  }
}
```

The right pattern is exponential backoff. The OpenAI SDK has retries built in (`max_retries=N`), or roll your own:

```python Python
import time
from openai import OpenAI, RateLimitError, APIError

client = OpenAI(api_key="sk-hapuppy-xxx", base_url="https://api.hapuppy.com/v1")

def chat_with_retry(messages, model="claude-sonnet-4-20250514", max_retries=5):
    for attempt in range(max_retries):
        try:
            return client.chat.completions.create(model=model, messages=messages)
        except RateLimitError:
            wait = min(2 ** attempt, 30)
            time.sleep(wait)
        except APIError as e:
            if e.status_code in (500, 502, 503):
                time.sleep(min(2 ** attempt, 30))
            else:
                raise
    raise RuntimeError("max retries exceeded")
```

See [Error Handling](/guides/errors) for the full retry strategy.

## Cost-Optimization Tips

<CardGroup cols={2}>
  <Card title="Use Prompt Caching" icon="bolt">
    Anthropic models auto-cache repeated system prompts. Claude Code's 40K system prompt is cached after the first call — subsequent calls save ~90% on the cached tokens.
  </Card>
  <Card title="Choose the right model" icon="scale-balanced">
    Don't default to Opus/o1 for everything. Most tasks fit Sonnet/4o; reserve high-multiplier models for hard reasoning or production agents.
  </Card>
  <Card title="Cap `max_tokens`" icon="ruler">
    Set a hard ceiling on response length. A runaway completion at 5× multiplier burns credits fast.
  </Card>
  <Card title="Batch when possible" icon="layer-group">
    For embeddings, send arrays of inputs in one request rather than one call per item — same token cost, fewer rate-limit hits.
  </Card>
  <Card title="Use streaming wisely" icon="play">
    Streaming doesn't cost less, but it lets you cancel early when the user has what they need — and that *does* save credits.
  </Card>
  <Card title="Moderate cheaply" icon="shield">
    Run [Moderation](/api-reference/moderations/create) on user input before forwarding to a high-multiplier chat model. It's near-free and rejects bad prompts before they cost credits.
  </Card>
</CardGroup>
